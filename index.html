Local Impact Automation Buildout

Started May 2, 2026 Saturday Target May 9, 2026 Saturday 6 days remaining Owner BG
The Local Impact 60-day engagement was graded against today's automation stack and landed at 28 fully automatable tasks, 25 AI-driven with human approval, 4 AI-assisted, 2 mostly human, and 7 irreducibly human. This sprint ships the foundation builds in seven days — the orchestration spine plus the highest-leverage onboarding pipeline — so the next live engagement runs on automation rails for Day 1 through Day 15. The thesis is not "replace the team." The thesis is "free the team's hours from execution so they can hold the seven irreducibly human moments well."

Build inventory

Build #1

Stage Trigger Sequencer

Shipped
Owner
Mack
Effort
Light (2 to 3 days)
Tasks covered
Orchestration spine for T1 through T15 plus future scheduled and event-driven touchpoints (T49, T55, T63, T64, T65)

Why this buildCheapest build, highest reliability dividend, foundation every other build sits on. Without this, no other build deploys.

Definition of done
  • Cron / launchd jobs configured and firing at correct day-offsets (Day 1, 2, 3, 7, 14, 28-30) from a synthetic engagement-start event
  • GHL webhook listener captures the canonical engagement events: deal-closed, contract-signed, payment-received, access-confirmed
  • Event-to-task dispatcher routes each event to the correct downstream handler (handler stubs are fine for this week)
  • Test client record running through Day 1 to Day 7 emits all expected trigger-fires in the correct order, observable in a log
  • Failure modes documented: webhook missed, cron missed, retry behavior, dead-letter queue
  • notify.py integration so any silent-action fires surface to BG per the standing rule
Build #2

Onboarding Pipeline (T1 through T15)

Shipped
Owner
Mack
Effort
Medium (3 to 4 days)
Tasks covered
T1, T2, T3, T4, T7, T9, T14, T15 fully automated. T5, T6, T11, T12, T13 generate drafts queued for human approval.

Why this buildHighest task count of any single build. Fires every time a new Impact System client closes. Every signed engagement benefits the moment they cross Phase 1.

Definition of done
  • T1 fires within 5 minutes of GHL deal-closed event, parameter-validated against canonical contract template
  • T2 watches OBS output, uploads to Vimeo, transcribes via Whisper, runs locked sales-eval prompt, posts structured eval back to GHL
  • T3 fires on DocuSign completed event, generates invoice, sends with reminder cadence configured
  • T4 fires on payment-received webhook, builds Drive folder structure with correct ACLs, appends client across all tracker tabs
  • T7 polls access-status at 48h post-onboarding, sends templated follow-up with Calendly link if access still missing
  • T9 dispatches Internal Handoff Email A on access-confirmed event
  • T14 fires on Day 3 with same logic as T7
  • T15 polls questionnaire-status, sends Email 5 reminder if not returned by Day 3-4
  • All eight handlers integrated with Build #1 trigger spine
  • End-to-end test: synthetic engagement-start event yields all eight handlers firing in correct order with correct artifacts

Risks and decisions

Top risks (ranked)

  • GHL webhook reliability gaps. Polled fallback that reads GHL state on a schedule and reconciles against missed webhooks. Built into Build #1 from the start.
  • DocuSign and Stripe API setup time underestimated. Timebox API setup to Day 4 morning. If either is not green by Day 4 EOD, escalate to BG and consider deferring T1 or T3 to Build #2.5.
  • Mack effort estimates too tight for Build #2. Prioritize the four highest-leverage handlers (T1, T3, T4, T9) for guaranteed ship. The other four (T2, T7, T14, T15) are stretch goals.
